# Choplifter Clone — Asset Pipeline

> Covers Mode 2 (Modern Pixel Art) and Mode 3 (Hi-Res) assets only.  
> Mode 1 uses extracted Apple II sprites — see [DESIGN.md §6.2](DESIGN.md).  
> All pipeline scripts live in `src/tools/`. All generated assets land in `assets/`.

---

## 1. Overview

Every asset except Mode 1 sprites is generated by automated tooling managed through VS Code.
The human role is: approve design decisions, run one-time setup, then ask for generation.
The assistant does the rest using MCP tools and pipeline scripts.

| Asset Type | Tool Stack | Requires | Cost |
|---|---|---|
---|
| Sprites (Mode 2) | Scenario MCP (VS Code) → ImageMagick → Pillow post-process | Scenario Pro account ($45/mo) | Credits (~150 for full set) |
| Sound Effects | Python (numpy/scipy) → ffmpeg | None | Free |
| Music | Python (midiutil) → FluidSynth → ffmpeg | None | Free |

**Why Scenario over generic image APIs:** Scenario supports training a **custom style model** from a small set of reference images. All 145 sprites are then generated from that one model, guaranteeing visual consistency — they look like they belong in the same game. Generic APIs (Replicate, DALL-E, etc.) generate each sprite independently with no style memory, producing an incoherent sprite set.

**Why not Replicate:** Zero style consistency across generations. Rejected.

**Scenario MCP integration:** Scenario's MCP server connects directly to VS Code Copilot. The assistant generates sprites through conversation using MCP tools (`train`, `run_model`, `display_asset`) — no Python API scripts needed for generation. Python scripts handle post-processing only (palette quantize, background removal).

**Web/mobile compatibility:** All audio output is OGG Vorbis. All sprites are PNG with alpha. Both formats are fully supported by Godot's web and mobile exports.

### 3.1 How It Works

**Phase 1 — Style Model Training (once)**
```
1. Collect 10–20 reference images that define the desired art style
   (pixel art military/rescue game, side-scrolling, flat colors, clean silhouettes)
2. Assistant calls Scenario `train` tool to train a custom LoRA model
3. Training takes ~15 minutes; model is saved to the Scenario project
4. All subsequent generation uses this model → guaranteed style consistency
```

**Phase 2 — Sprite Generation (per group)**
```
For each sprite group:
  1. Assistant calls `run_model` with the trained style model + sprite-specific prompt
  2. 4 candidates generated per sprite
  3. Assistant calls `display_asset` to show candidates inline
  4. Assistant auto-selects best candidate by silhouette/quality heuristic
  5. Candidate downloaded to assets/graphics/mode2/_candidates/<name>/
  6. Auto-selected sprite is post-processed (Phase 3)
```

**Phase 3 — Post-processing (automated Python)**
```
For each selected sprite:
  a. ImageMagick: resize to exact target pixel dimensions
  b. ImageMagick: quantize to Endesga 32 palette (max 32 colors)
  c. Pillow: detect and remove background color → alpha channel
  d. Pillow: score silhouette clarity; flag if below threshold
  e. Save to assets/graphics/mode2/<group>/<name>.png
```

### 3.2 Style Reference Images

Before training, collect 10–20 reference images that capture the target style:
- Clean pixel art, 32×32 to 64×64 sprite scale
- Military/rescue game aesthetic (vehicles, characters)
- Flat colors, clear silhouettes, minimal anti-aliasing
- Top candidates: Broforce sprites, Metal Slug sprites (as style reference only — not used in-game)

The assistant will guide collecting these before initiating training.

## 4. Sound Effects Pipeline

**Script:** `src/tools/generate_sfx.py`

No API required. All sounds are synthesized from waveform parameters using
**numpy** + **scipy** and exported via **ffmpeg**.

> **Note:** A standalone Python sfxr port does not exist on PyPI. Waveform
> synthesis with numpy/scipy provides equivalent results with full parameter
> control and is the correct approach here.

### 4.1 How It Works

Each SFX is defined as a parameter block (waveform type, frequency envelope,
amplitude envelope, noise, pitch sweep). The script synthesizes the WAV in Python,
then converts to OGG with ffmpeg.

```python
# Example SFX definition (in src/tools/config/sfx_spec.py)
SFX_SPECS = {
    "bullet_fire": {
        "waveform": "square",
        "freq_start": 880, "freq_end": 440,
        "duration": 0.08,
        "amplitude_envelope": "decay",
        "noise_mix": 0.05,
    },
    "explosion": {
        "waveform": "noise",
        "freq_start": 200, "freq_end": 50,
        "duration": 0.4,
        "amplitude_envelope": "exp_decay",
        "noise_mix": 1.0,
        "lowpass_hz": 800,
    },
    # ... etc
}
```

### 4.2 Complete SFX List

| File | Description | Character |
|---|---|---|
| `engine_loop.ogg` | Chopper engine (seamless loop) | Low rotor hum, ~80 Hz fundamental |
| `bullet_fire.ogg` | Player bullet fired | Short square wave pitch-down sweep |
| `bullet_impact.ogg` | Bullet hits something / misses | Soft noise thud |
| `tank_fire.ogg` | Tank shell fired | Low square pulse + noise |
| `jet_fire.ogg` | Jet missile launched | Mid-range pitch-up sweep |
| `bomb_drop.ogg` | Bomb released | Brief whistle down |
| `explosion.ogg` | Any entity explodes | Noise burst with lowpass |
| `explosion_small.ogg` | Bullet impact explosion | Shorter version of above |
| `hostage_board.ogg` | Hostage boards chopper | Short ascending 3-note beep |
| `hostage_death.ogg` | Hostage killed | Descending minor 3rd tone |
| `landing.ogg` | Chopper lands | Thud + brief settle noise |
| `alien_crackle.ogg` | Alien saucer (3 pitch variants) | Electrical crackle, 3 files |
| `victory_sting.ogg` | Mission complete | 4-note ascending fanfare |
| `loss_sting.ogg` | Game over | 3-note descending phrase |
| `fire_telegraph.ogg` | Enemy charge tell (Mode 2+) | Brief rising tone, 0.3s |
| `stranded_warning.ogg` | Stranded hostage timer (Mode 2+) | Slow pulse beep |
| `fuel_low.ogg` | Fuel warning (Mode 2+ Reimagined) | Repeating low pulse |
| `bounce.ogg` | Chopper bounce landing (Mode 2+) | Compressed thud |
| `ui_select.ogg` | Menu navigation | Short click |
| `ui_confirm.ogg` | Menu confirm | Two-tone beep |

**Total: 21 files.** All Mode 1 compatible except where noted (Mode 2+).

The engine loop uses a seamless-loop technique: the waveform is phase-aligned at
loop point so Godot can loop it without clicking.

### 4.3 Running the SFX Pipeline

```bash
# Generate all SFX (no API, ~5 seconds total)
python3 src/tools/generate_sfx.py

# Single SFX
python3 src/tools/generate_sfx.py --sfx explosion

# Tune a specific SFX (outputs WAV for preview before committing to OGG)
python3 src/tools/generate_sfx.py --sfx bullet_fire --preview
```

Preview mode writes `assets/audio/sfx/_preview/<name>.wav` for local playback.
Once approved, re-run without `--preview` to produce the final OGG.

## 5. Music Pipeline

**Script:** `src/tools/generate_music.py`

No API required. Music is composed in Python using **midiutil**, rendered to WAV
with **FluidSynth** and the chiptune soundfont, and converted to OGG with ffmpeg.

### 5.1 Dynamic Layer Architecture

The dynamic music system uses **three looping OGG files per biome**, crossfaded
by `AudioManager.gd` based on game state:

| Layer | File Pattern | When Active |
|---|---|---|
| Calm | `music_<biome>_calm.ogg` | No enemies in aggro range, no active fire |
| Tension | `music_<biome>_tension.ogg` | Enemies nearby or approaching |
| Action | `music_<biome>_action.ogg` | Taking fire, rescue in progress |

Additionally:
- `music_sting_victory.ogg` — mission complete fanfare (one-shot)
- `music_sting_loss.ogg` — game over phrase (one-shot)
- `music_sting_sortie.ogg` — sortie banner music (one-shot)

All three layers for a biome share the same **BPM, key, and loop length** so
they crossfade cleanly. Layers build on each other: tension adds percussion to
calm's melody; action adds lead on top of tension.

### 5.2 Composition Structure

Each biome has a distinct musical character:

| Biome | Key | BPM | Character |
|---|---|---|---|
| Desert | A minor | 120 | Sparse, echo-y, slightly Arabic |
| Jungle | E minor | 135 | Driving, dense, tribal percussion |
| Arctic | D minor | 100 | Slow, cold, wide intervals |
| Tropical Island | C major | 140 | Upbeat, Caribbean-influenced |
| Alien World | No tonal center | 150 | Atonal, dissonant, alien |

**Structure per track:** 8-bar loop. Calm layer = melody only. Tension = +drums.
Action = +lead countermelody. All loops are exact multiples of the same bar length
so they phase-lock when crossfaded.

### 5.3 MIDI → OGG Pipeline

```
midiutil (Python) → .mid file
  → FluidSynth --audio-driver=file --soundfont=chiptune.sf2
  → .wav file (44100 Hz, stereo)
  → ffmpeg -c:a libvorbis -q:a 4
  → .ogg file
```

The FluidSynth rendering step uses specific instrument patches from the chiptune
soundfont (e.g., patch 80 = Square Wave lead, patch 38 = Synth Bass 1). The
mapping is defined in `src/tools/config/music_instruments.json`.

### 5.4 Running the Music Pipeline

```bash
# Generate all music (no API, ~30 seconds for FluidSynth rendering)
python3 src/tools/generate_music.py

# Single biome
python3 src/tools/generate_music.py --biome desert

# Single layer only
python3 src/tools/generate_music.py --biome desert --layer calm

# Preview as WAV (before OGG conversion)
python3 src/tools/generate_music.py --biome desert --layer calm --preview
```

### 5.5 Music for Mode 1

Mode 1 music is off by default. If the player turns it on, Mode 1 uses the
**Desert biome** music (since Mode 1 has no biomes). The same OGG files are
reused — no separate Mode 1 music generation needed.

## 6. Complete Pipeline Run

Sprite generation is done interactively through VS Code Copilot (Scenario MCP).
SFX and music are fully automated scripts.

```bash
cd /home/chris/Github/choplifter-clone

# 1. Generate SFX (fast, no API, ~5 seconds)
python3 src/tools/generate_sfx.py

# 2. Generate music (no API, ~30 seconds FluidSynth rendering)
python3 src/tools/generate_music.py

# 3. Generate Mode 2 sprites (via VS Code Copilot + Scenario MCP)
#    Tell the assistant: "Generate the <group> sprites using the Choplifter style model"
#    Then post-process each group after generation:
python3 src/tools/postprocess_sprites.py --group chopper_side

# 4. Consistency pass
python3 src/tools/postprocess_sprites.py --pass consistency
python3 src/tools/postprocess_sprites.py --pass fix   # if any flagged

# 5. Verify outputs
python3 src/tools/verify_assets.py
```

`verify_assets.py` checks that all expected files exist, are valid PNG/OGG,
and meet minimum size/quality thresholds. Prints a pass/fail report.

## 9. Versioning and Regeneration

Generated assets are committed to git with a generation metadata sidecar:
`assets/graphics/mode2/.generation_manifest.json` and
`assets/audio/.generation_manifest.json`. Each entry records:
- Script version
- Model/config used
- Timestamp
- Hash of the config that produced it

When `postprocess_sprites.py` runs, it compares the current config hash against the
manifest and only reprocesses sprites whose source candidate has changed. This makes
incremental updates cheap — tweaking one sprite's post-processing only reprocesses that sprite.
